# Lightsail Terraform Stack

This module provisions a cost-conscious single-node production setup for this repo on Amazon Lightsail:

- 1 x Lightsail instance (Amazon Linux 2023, default `medium_2_0`)
- 1 x Static IP attached to instance
- Public firewall ports (default `22`, `80`, `443`)
- Optional Lightsail DNS zone + A records
- Optional Lightsail alarms
- Cloud-init bootstrap that installs Docker/Buildx/Compose, clones this repo, writes `deployment/aws/.env`, and starts the stack.
- Static IP behavior: if the named static IP already exists, Terraform reuses it; otherwise it creates it.

## Prerequisites

- Terraform `>= 1.5`
- AWS credentials configured (`aws configure` or env vars)
- Existing Lightsail key pair (default: `LightsailDefaultKeyPair`)
- `jq` installed locally (used by Terraform external data script for static IP lookup)

## 1) Configure variables

```bash
cd infra
cp terraform.tfvars.example terraform.tfvars
```

Edit `terraform.tfvars` at minimum:

- `db_password`
- `cors_origin`
- `admin_emails`
- `repo_clone_url` (if not using default repo)
- `domain_name` and `create_lightsail_dns_zone` (if managing DNS here)

## 2) Init / plan / apply

```bash
terraform init
terraform plan
terraform apply
```

## 3) Get useful outputs

```bash
terraform output instance_public_ip
terraform output api_url
terraform output ssh_command
terraform output bootstrap_check_command
```

## 4) Verify bootstrap

SSH into the instance and check bootstrap + containers:

```bash
ssh -i /path/to/key.pem ec2-user@<PUBLIC_IP>
sudo cat /var/lib/poker-bootstrap/status
sudo cat /var/lib/poker-bootstrap/status.json
sudo tail -n 200 /var/log/poker-bootstrap.log
cd /opt/poker-game/deployment/aws
docker compose ps
curl -s http://localhost:3000/health
```

## Notes

- JWT secrets are generated by Terraform random provider and written into `.env` by bootstrap.
- `.env` is generated during bootstrap at:
  - `/opt/poker-game/deployment/aws/.env`
- Bootstrap writes status markers at:
  - `/var/lib/poker-bootstrap/status`
  - `/var/lib/poker-bootstrap/status.json`
- This module intentionally keeps architecture simple and inexpensive (single-node compose stack). For HA/managed services, split DB/Redis into managed services later.
